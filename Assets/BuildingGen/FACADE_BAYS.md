# Facade Bay Planner (v0.5)

The Facade Bay Planner is an opt-in facade-layout system for Yazd-style buildings. It replaces independent random placement of facade features with one reservation map per wall, so doors, windows, iwans, arcade bays, niches and intentional blank areas do not overlap.

## Quick demo

In Unity run:

`Tools > BuildingGen > Create Facade Bay v0.5 Demo`

The command creates simple sample prefabs, a `FacadeBayCatalog`, a sample `YazdBuildingStyle`, and a generated courtyard building.

## Production workflow

1. Model the visible door/window/iwan/arcade/niche in 3ds Max.
2. Export the asset and create a Unity prefab.
3. Keep the prefab root pivot at the bottom-center of the opening.
4. Use local +Y for up and local +Z for the outward facade direction.
5. Add `FacadeBayDefinition` to the prefab root.
6. Set `Kind`, `Nominal Width`, `Nominal Height`, `Sill Height`, clearances, floor rules and allowed surfaces.
7. If the bay must cut the wall, add a closed cutter mesh that crosses the complete wall thickness and assign it to `Cutter Root`.
8. Add the prefab to a `FacadeBayCatalog`.
9. On `BuildingGenerator`, enable `Use Facade Bay Planner`, assign the catalog, choose the eligible surfaces, and generate.

## Reservation behavior

Each placed feature reserves a horizontal interval plus its `Neighbor Clearance`. A reservation can also span multiple floors via `Floor Span`.

Typical values:

- Window: floor span 1.
- Door: floor span 1, ground floor only.
- Iwan: floor span 2 or more.
- Arcade: usually floor span 1, courtyard/front surfaces.
- Niche: floor span 1.
- Blank: generated from the catalog's blank weight and blank width.

A multi-floor iwan therefore blocks windows that would intersect it on both floors.

## Legacy entrance compatibility

`Keep Primary Entrance Door` lets the original generator place the main entrance first. The new planner detects that opening and reserves its interval before planning the remaining facade. This keeps the existing hashti / bent-corridor workflow available while the rest of the facade uses the new reservation system.

When Facade Bay Planner is enabled, legacy random windows, legacy iwan placement and legacy courtyard arcade placement are temporarily bypassed during generation. They are not removed from the component and are restored immediately after the base mass is generated.

## CSG

Visible prefabs are placed even when CSG is unavailable. Wall cutting requires ProBuilder experimental CSG, consistent with the existing opening/iwan workflow.

If CSG is enabled, the cutter is subtracted from the host wall and then disabled. `Bake Copy` removes `FacadeBayDefinition` components and cutter objects from the baked copy.

## Current scope

v0.5 focuses on straight facade segments generated by `BuildingGenerator`. `WallSpline` remains a separate v0.4 workflow. Planned WallSpline upgrades include gate openings, pillars/buttresses, wall niches, end caps, broken top profiles and terrain conforming.
